# newbound_nebula

Make your personal Newbound network a virtually private one with
[Nebula](https://github.com/slackhq/nebula), Slack's open-source overlay
network. The Nebula app lets you install the nebula binary, create
networks, sign member certificates, and roll the overlay out to every
Newbound peer you have admin access to — from one UI.

## Install

This is a drop-in Newbound library. On any Newbound instance:

1. Open the **Dev** app → shelf → **git import**, and import
   `https://github.com/mraiser/newbound_nebula` (or call
   `dev.github.import` with that URL). The platform clones the repo into
   `repositories/nebula` and links `data/nebula` + `runtime/nebula` into
   place.
2. Restart the Newbound software once (the first install adds the
   `nebula` hot-reload crate to the build; after this one restart,
   library code updates hot-load with no further restarts).
3. Activate the **Nebula** app in the app list (or add `nebula` to the
   `apps=` line of `config.properties`).

To update: `dev.github.update` with library `nebula` (or `git pull` in
`repositories/nebula` followed by a rebuild). To uninstall:
`dev.github.remove` — your keys live under
`runtime/nebula/networks/`, so read the warning it gives you before
confirming.

## Use

Open the Nebula app:

- **Install a release** — pick a version and platform binary from the
  official nebula releases; it is downloaded (curl) and unpacked into
  `runtime/nebula/bin/`.
- **Create a network** — name, subnet pattern, port. The CA and this
  host's certificate are generated by `nebula-cert` directly into
  `runtime/nebula/networks/<name>/`; the CA key never leaves that
  folder.
- **Add members** — pick a peer, an overlay IP, and optional firewall
  groups. The member's certificate is signed here and delivered to the
  joining peer over Newbound's encrypted peer channel; the peer writes
  it into its own `runtime/nebula/networks/<name>/`.
- **Lighthouses** — mark publicly reachable peers so members behind NAT
  can find each other.
- **Run it** — install the generated systemd unit and start/stop the
  tunnel per network, on any admin peer, from the same UI.

All nebula commands are admin-only: they manage keys and shell out to
`sudo systemctl`.

## Security notes

- Nothing secret is ever committed or synced: private keys and network
  configs live only under `runtime/nebula/networks/<name>/`, which is
  gitignored here and stays on the instance that owns it.
- The network's CA key exists only on the instance that created the
  network. Member keys travel once, to the joining peer, over the
  already-encrypted Newbound peer channel.
- Removing a member deletes its folder but does not revoke the issued
  certificate — rotate the CA (recreate the network) to force a member
  out.

## Layout

- `data/nebula/` — the store library (source of truth): four controls
  (`nebula`, `lighthouse`, `network`, `member`) and the 14 commands.
- `nebula/` — the generated FFI dylib crate, tracked so the Rust is
  reviewable; regenerated from the store by `newbound rebuild`.
- `runtime/nebula/` — the app shell (`app.properties`, `src/html`).
  At runtime it also holds local values: the nebula binary (`bin/`) and
  your networks (`networks/`) — never committed.

## Dependencies

A working [Newbound](https://github.com/mraiser/newbound) installation,
plus `curl` and `tar` on the PATH (used to fetch and unpack nebula
releases). No third-party Rust dependencies.
